# Benchmarks

独立的基准测试脚本，用于衡量各并发组件的热路径吞吐与内存行为，并记录历次重构的实测对比。

## 运行方式

唯一依赖是 Swoole，直接运行：

```bash
php benchmarks/worker-pool.php
php benchmarks/single-flight.php
php benchmarks/barriers.php
php benchmarks/semaphore.php
```

在 Docker 容器内（如本仓库开发用的 sgc 容器）：

```bash
docker exec sgc sh -c 'cd /app && php benchmarks/worker-pool.php'
# 其余脚本同理
```

## 场景说明

### worker-pool.php

| # | 场景 | 测什么 |
|---|---|---|
| 1 | 同步任务吞吐（cap 10） | 每任务完整周转（取 worker → 执行 → 归还）的热路径成本 |
| 2 | GC 常驻时吞吐（cap 20） | 开启 `collectInactiveWorker` 后的常驻开销 |
| 3 | 高空闲流转（cap 50） | 批量异步任务 + 整批空闲，空闲容器进出最频繁的形态（该场景受任务自身 `usleep` 支配，数字变化只反映开销占比） |
| 4 | 内存：池创建销毁 | 50 个池的 创建 / 任务 / 全量回收 / 销毁 周期，验证零泄漏 |
| 5 | 内存：长运行单池 | 同一个池 50 轮 忙闲交替 + 全量回收 + 按需再生，反复锤打 GC 路径 |

### barriers.php

| # | 场景 | 测什么 |
|---|---|---|
| 1 | CounterBarrier 汇合吞吐 | 管理器批次汇合（500 波 × 10 方），含屏障创建/打破/清理全周期 |
| 2 | DoubleBarrier 组队吞吐 | enter + execute + leave 完整组队（300 组 × 3 方） |
| 3 | 内存 | 2500 个屏障批次的生命周期，验证条目零残留 |

### single-flight.php

| # | 场景 | 测什么 |
|---|---|---|
| 1 | 合并吞吐 | 10000 并发 `do` 同一 key（processor 仅执行 1 次），整体请求合并机制的成本 |
| 2 | leader 建销吞吐 | 唯一 key 串行 `do`，leader 创建/共享/清理的完整生命周期成本 |
| 3 | 内存 | 唯一 key 生命周期循环，验证条目零残留 |

### semaphore.php

| # | 场景 | 测什么 |
|---|---|---|
| 1 | 无竞争快路径 | `acquire`+`release` 不等待时的每操作成本 |
| 2 | 高竞争路径 | 20 协程争抢 4 令牌，含 FIFO 排队与唤醒 |
| 3 | 内存：管理器生命周期 | 唯一 key 的完整生命周期循环，双点测量（预热后 5k→10k、10k→50k）验证 WeakMap 条目随对象销毁自动蒸发、增长恒为 0 |

## 历史结果

> **对比须知**：绝对值随机器与运行状态波动（同一份代码两次运行可有 ±15% 差异），跨轮对比请以**同一会话内先后运行**为准；下表每一轮的前后数字均来自同一次会话的对照实测（PHP 8.3.3 + Swoole）。

### WorkerPool

| 重构轮次 | 同步任务 (tasks/s) | GC 常驻 (tasks/s) |
|---|---|---|
| 手写最小堆（`Heap/`，重构前） | 208,500 | 205,965 |
| ① 删除堆，GC 改为扫描空闲链表 | **321,326（+54%）** | **297,565（+44%）** |
| ② 手写链表 → `SplQueue`/`SplStack`，GC 改为端式弹出 | **265,466（+8%）**¹ | **332,291（+12%）**¹ |

¹ ② 的同会话对照基线为 245,242 / 297,565（与 ① 后数字的差异是运行间波动）。

高空闲流转场景（usleep 支配）各轮稳定在 2,200~2,350 tasks/s。

### Semaphore

| 版本 | 无竞争 (ops/s) | 高竞争 (ops/s) |
|---|---|---|
| `SplObjectStorage`（当前） | 3,019,870 | 2,541,170 |

手写 `List/` 版本在重构时未做吞吐测量，当前版本数字留作未来重构的基线。

### 内存

所有内存场景增量 **0 bytes**。semaphore 场景 3 采用双点测量并先做 5k 周期预热——首次运行若看到 ~1KB 量级的单次噪声，属于哈希桶预热，第二测量点起应恒为 0；若两点均为正且随周期数放大，即为泄漏信号。
